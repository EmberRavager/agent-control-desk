# 产品功能状态与交付清单

核对日期：2026-11-05。以当前源码和已执行验证为准。

“已实现”表示代码链路存在；“隔离验证”使用 Fake 模型、Agent、微信接口及凭证存储；真实账号、原生窗口和跨平台验收另外列出。编译或测试通过不能替代真实任务成功。

## 当前软件定位

ACD 是本机 Agent 的统一任务入口。主会话接收消息，总控判断新任务、补充、停止、查询或澄清；执行任务的 Agent 使用自己的账号与工具配置。CLI、桌面端和个人微信复用同一个 Runtime、任务编号及持久化状态。CLI 的 `acd sessions` 可只读查看同步的原生会话，`acd tasks` 保留为 ACD 自己的任务。

## 补齐顺序与验收

1. **打通本人真实使用闭环**：独立总控模型调用 → Codex/Claude 执行 → 原生桌面进展 → 个人微信扫码和双向文字 → 停止/回答 → 检查完成。记录实际结果；不以模拟测试替代。
2. **补执行覆盖**：OpenCode、Pi 已完成首轮原生执行与续接验证；后续分别核对 OpenClaw、Hermes、DeepSeek Harness 的官方执行协议。每个适配器分别验收创建、结果、错误、停止、续接和授权能力，不能共用“支持全部”的标签。
3. **补可靠恢复与使用反馈**：扩展真实意图识别案例集、任务恢复核对、完整历史浏览、备份恢复与诊断信息。未确认外部效果仍保留未知状态。
4. **完成跨平台交付**：Windows 执行与凭证存储验证、Mac/Windows 安装包、退出/升级时的后台生命周期和正式发布验证。

个人偏好与受限流程学习已实现，范围见[个人记忆](configuration.md#个人记忆)。情绪、主动聊天、自进化和持续客服属于此前探索方向，当前没有实现，也不应算作这个路由中心第一版已经交付的功能。MCP 和原生工具由各执行 Agent 自身配置管理；ACD 暂无独立 MCP 管理器。单项定时任务现已单独实现；复杂依赖工作流不在本轮范围。
