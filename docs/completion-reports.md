# 完成报告与建议

执行端结束一轮时，ACD 保存判定任务。总控对照用户要求、最终公开答复以及上一次有效判定，只有认定已产生新的完整交付时，才在总控对话发布结果和一至三条建议。托管任务仍保留「确认完成」供用户验收。模型判断本身不会启动任务或代用户验收。

## 判定依据

- 「继续」等补充可以承接同一任务或原生会话上次的目标。未取得最终答复的轮次只保留用户要求，不调用模型。阶段进展、等待必要确认、证据不足、闲聊与重复交付不发完成报告。
- 总控在一次请求中判定是否交付，并为交付结果生成建议。判断需引用这一轮最终答复中实际存在的证据行。对用户点名且最终答复引用的项目文件，本机可以核对有限的相对路径、存在性和大小。这个检查不遍历项目，也不读取或上传文件正文。其余交付以执行端提供的证据为依据。
- 原生会话取有限的公开用户要求和最终答复，隐藏内部会话；不提交推理、工具参数或工具返回正文。托管任务继续使用自己的目标和执行结果。配置远端总控模型时，公开片段和核对元数据会发往所选服务。
- 同一执行重复上报或后台重启不会重新发送已发布报告。同一目标和结果未变会去重，旧要求对应的迟到判断不能覆盖已修改的托管任务。

## 查看和恢复

确认交付后，报告保存在本机，消息中心按报告编号定位，同一份结果不会因重复刷新产生新的未读提醒。即使原消息已离开最近 200 条对话，也可从该条通知打开原报告。已启用微信报告推送时，将新交付的结果和建议加入绑定者的发件队列。普通任务进展和待授权提示分别沿用原设置。

判定模型出错最多自动尝试两次，间隔至少 30 秒；连续失败后可从失败记录重试，重试只做判定。已发布的旧版报告保留历史显示。微信接口受理和手机实际显示分别核验。
