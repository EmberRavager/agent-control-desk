# 消息与草稿恢复

网络发送、模型理解和任务执行是三个阶段，恢复方式不同。应用不会因为断线、重开窗口或后台重启而自动重放任务。

| 状态             | 恢复入口                                      | 约束                                                                   |
| ---------------- | --------------------------------------------- | ---------------------------------------------------------------------- |
| 未确认接收       | 重试发送                                      | 复用原消息编号、内容、目录与目标；服务端已收到时返回原回执，不重复理解 |
| 理解失败／已中断 | 原消息上的“重新判断”或 `acd retry <消息编号>` | 只有后台确认尚未进入动作应用阶段、且保留原请求范围时才开放             |
| 执行结果待确认   | 查看原生执行后人工核对                        | 不能通过重新判断重跑已提交的动作；按任务恢复规则处理                   |

## 原消息重新判断

失败或后台中断的用户消息保留原工作目录和选中任务。重新判断使用当前模型与最新任务快照；更新同一条用户消息，不再复制一条到对话。重复点击在途请求共用当前理解，已完成的重试返回已有回执，不重复推理或执行。

后台仅在未进入动作应用的边界标记 `routing.retryable: true`。正常接收的网络重发依旧只查回执，不自动重新调用模型。已应用决策、可能部分提交、缺少原目录或目标的历史记录均不能通过此入口重放；目录改变或原目标不存在时，会要求重新确认。

```sh
acd retry <提交回执中的消息编号>
```

本机接口为 `POST /api/messages/:messageId/retry`，正文为 `{}`，要求本机认证；返回 202 与原消息回执。`routing.attempt` 记录显式重新判断次数。桌面和 CLI 通过 `routing-retry` 能力检查识别旧后台。升级这类桌面操作需要完整退出并重开客户端，单纯刷新 renderer 不能更新 main 的 IPC 白名单。

## 关窗与草稿

桌面自动保存输入文字、工作目录、任务目标和原问题编号。它使用 Electron 客户端本地存储，按 ACD 数据目录隔离，不复制已接收的完整对话历史。重开后恢复草稿；原问题已处理或原目标不可用时，保留文字并提示重新确认，避免把旧回答误投给其他任务。

发送前先持久保存稳定消息编号和请求范围，再清空输入框并提交网络请求。窗口关闭时仍未确认的记录恢复为提示，不自动发送；新输入与旧记录分别保存。收到有效回执或服务端快照确认后删除本机重试记录。清理失败也不会把已接收消息说成未发送，后续同步可再次核对。

“移除提示”只删除本机恢复记录，不停止或撤销后台任务。超过 20,000 字符的文字保留为可编辑草稿，发送前需要缩短。草稿格式损坏时先保存恢复副本；写入失败时保留输入，本次提交不会发起。

草稿可能包含未发送的私人文字，属于本机用户数据。API Key 和微信登录凭证继续使用既有系统凭证存储，不作为草稿字段保存。复制后台数据目录可备份 SQLite 与 JSONL，**不包含桌面客户端本地存储的草稿**；迁移草稿还需要保留 Electron 用户数据目录，当前没有备份／恢复向导。

## 验证范围

已用隔离 HTTP、CLI、存储和组件交互验证：重复点击、失败重试、跨重启中断、缺失目录／目标、关窗恢复、不同数据目录隔离、原问题关联、损坏记录、磁盘写入失败、超长输入及已接收消息的本机确认失败。

另在隔离目录制造一次模型 HTTP 503，再切回本机 Qwen，经真实 `acd retry` 恢复同一条问候消息，未启动执行 Agent。新的桌面窗口实机加载、系统通知和 Windows 行为仍需分别验收，不能用这些隔离检查替代。

## 结束已停止执行的任务

“待检查”任务可通过“确认完成”记录用户验收。用户也可结束仍处于“待检查”或“失败”的任务，任务随后进入“已停止”，保留已有交付结果并关闭未解决的问题。对应的 `POST /api/tasks/:taskId/stop` 操作在确认没有活跃执行连接或占用时，只更新本机任务状态；重复操作保持幂等。

仍在执行的任务继续等待执行端确认停止。状态待确认的任务保留原有人工核对流程。
