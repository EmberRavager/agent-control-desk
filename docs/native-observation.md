# 原生会话只读观测

ACD 自己发起的执行保存在 `tasks`；原生客户端已经存在的会话通过 `observations` 独立提供，不伪造成 ACD 任务。

## 当前范围

首个适配器针对已选择管理的 Codex，每 5 秒同步一次。优先通过官方 `codex app-server proxy` 读取已开放控制端点的实例；端点不可用时，在当前用户的 Codex 进程所持有的可写记录中提取执行事件。两种来源都不会启动、恢复、追加或停止原生会话。

官方接口只调用 `initialize`、`thread/loaded/list`、`thread/read(includeTurns:false)`。保留会话 ID、名称、工作目录、运行状态和观测时间；不保留响应中的 preview、turns 或其他聊天正文，不写入会话日志和任务数据库。总控理解消息时，这些元数据会随上下文发送到用户配置的模型服务，纯状态同步不发送正文。协议参考 [OpenAI 官方说明](https://learn.chatgpt.com/docs/app-server)。

- `active` 显示正在执行；等待用户输入或授权的 activeFlags 显示等待处理。
- `idle` 显示当前空闲，不等于任务已验收完成。
- `notLoaded`、断线或状态不可核验显示状态未知，不继续保留“正在执行”。
- `systemError` 显示发生错误，在原生客户端查看原因。

正在由 ACD 管理的原生会话不重复计数；ACD 任务结束后，同一会话在原生端重新执行时可重新被观测。切换管理对象后，旧请求结果不会重新加入已取消选择的 Agent。

选中来源中已观察到的执行中或等待输入会话，占用其工作目录。ACD 的普通任务和定时任务会等待同一真实目录或父子目录的占用释放。明确观测到空闲、失败，或官方接口确认此前从该接口看到的会话已卸载后，队列会自动重试。断线、状态未知或本地事件列表暂缺记录时保留已知占用。如果来源长期失联，可先在原生客户端核实执行已结束，再取消接入该来源以解除等待。占用仅保存在当前后台进程中，每轮观测之间从原生客户端新建的执行仍可能与 ACD 重叠。

## 本地执行事件来源

当前桌面实例没有开放官方控制端点，使用本地执行事件补齐运行状态：

- 通过 `lsof` 核验当前用户 Codex/ChatGPT 进程持有的可写 rollout 文件，只接受 `.codex/sessions` 内的普通文件，拒绝越界和符号链接逃逸。
- 不扫描已关闭的全部历史会话。对进程持有的记录提取 session_meta 的 ID、目录以及 task_started、task_complete、turn_aborted 等运行字段；不保留用户消息、推理、命令和工具输出正文。
- 首次增量投影后只缓存文件身份、偏移和状态字段。跳过大消息正文；半行等待完整写入，过大或损坏的状态事件降级为未知。
- 本地记录只有在当前轮次最近 5 分钟内有可核验的执行事件，且写入进程仍持有文件时，才计入进行中。已观测到的执行超过该窗口仍无新进展，或写入进程消失但缺少结束事件时，显示状态未知。后续执行事件可恢复运行状态，明确的结束事件仍按原规则处理。官方接口返回的实时状态不受该窗口限制。
- 派生会话会复制父记录且重写写入时间，因此按子会话的创建边界和原生执行 ID 归属过滤继承事件，不把父会话的旧执行计入子会话。
- 已观察到的会话结束后，短期保留本轮结束状态供核验；不把历史空闲会话批量加入任务列表。

`AgentObservation.source` 区分 `runtime-api` 和 `run-events`，详情显示来源和观测时间。本地事件格式变化会影响兼容性；当前仅在 Mac 实机核验，Windows 本地事件适配尚未实现。

## 界面和总控

原生执行与等待处理的会话进入侧栏对应分组。第一行显示 AI 生成的简短任务标题，第二行显示 Agent 名称与运行状态；目录与编号不占用标题。点击后在右侧主区域显示 AI 任务视图，不使用弹窗。顶部展示任务名和目标，当前步骤与下一步沿同一条进展线排列；有明确阻塞时单独提示。以上文字由总控模型基于当前公开执行片段总结，不把计划节点当作已完成步骤。原始用户要求、模型解读、会话编号、目录、事件时间和来源统一收在默认折叠的“详情与来源”中。空字段或纯标点不显示栏目；分析更新失败保留最近结果并提供重试。空闲或近期结束的会话可从连接区查看。

无法取得状态时，侧栏显示“外部未同步”，连接区可以查看原因并重新同步。总控状态查询同时读取 ACD 任务和已观测会话；不能把 ACD 空列表当作电脑里没有任务。

`POST /api/observations/refresh` 使用现有本机认证和桌面 IPC 白名单，只触发一次只读同步。并发刷新共用同一轮请求；状态通过现有快照和 SSE 更新，不增加第二套任务生命周期。后台退出只关闭 ACD 自己的代理进程，不停止原生服务或任务。

CLI 通过同一快照查看原生会话：

```sh
acd sessions
acd sessions --json
```

`acd tasks` 保留为 ACD 自己发起的任务；`sessions` 返回观测来源和原生运行标识，不把它们变成可执行任务。未同步或空列表会说明当前可见范围，不能据此断言电脑中没有其他执行。

## AI 任务摘要的数据范围

新发现的执行中或等待处理会话自动生成任务标题，同时缓存同一次分析的详情；后台串行生成标题，不分析历史空闲会话。只读取已验证的当前执行范围内最近有限片段，保留首条真实用户要求及最近 3 条补充、5 条助手公开进展以及 8 个工具名称；每段限制 1,000 字符，并对常见 Key/Token/密码模式脱敏。内部推理、工具参数、工具输出、完整历史不会进入摘要模型。

这些公开片段会发送到用户配置的总控模型服务，本机已验证 Ollama Gemma 与 Qwen。运行分析原文不落盘，摘要只做短期内存缓存；首条要求与补充仅保留原生文件位置，按需读取。标题、目标与摘要解释用户要求，当前步骤仅解释执行进展。自动目标续跑的内部封套只提取 `<objective>` 内的用户目标，忽略续跑规则、预算和计数，避免将运行说明归为新需求或反复触发分析。没有用户要求时明确显示目标待同步，不从编译或测试动作猜测任务。同一要求的标题保持稳定，新增用户要求时可以更正；状态轮询不反复触发标题生成。后台初次标题分析失败至少等待一分钟再重试，也可以在详情中手动重试。

桌面窗口保留最近 50 份分析展示缓存，按会话、执行轮次、状态和总控模型隔离。重复打开时直接显示已有结果；30 秒内不重新请求，过期后保留旧内容并在后台核对；公开输入没有变化时复用结果，不调用模型。查看中的运行任务每 5 秒检查缓存是否已满 30 秒，达到更新间隔才请求分析；离开详情页或任务停止运行后不继续定时分析。手动“重新分析”可以跳过缓存，并发与切换时的在途请求合并。更新失败保留最近结果并限制自动重试频率。

切换模型会清空展示缓存，迟到响应不能重新写回；执行轮次或状态变化使用新的缓存记录。窗口重启后展示缓存不保留，后台 30 秒结果缓存仍可复用。运行状态同步维持约 5 秒一次，与模型分析更新时间分开显示。

AI 摘要属于对公开片段的归纳，不参与执行状态判定，不编造完成比例，不生成新任务或获得原生控制权限。片段不足时明确说明目标细节未同步。

`POST /api/observations/:nativeId/analyze` 接受 `{ force?: boolean }`，仅允许当前已观测的会话，返回 `{ title, summary, goal, currentStep, blocker, nextStep, generatedAt, model, basis, requirements }`。

正常结束后自动结果汇报与建议的触发、持久化及边界见 [结果汇报](completion-reports.md)。完成汇报会保存有限公开要求和结果用于重启恢复，与运行分析的临时缓存不同。

## 验证和限制

2026-11-03：已用隔离协议进程验证分页、状态映射、只读请求集合、正文剥离、断线降级、执行归属去重和取消选择后的结果隔离；界面验证了原生会话计数、只读详情与重试。

本机真实 `codex app-server proxy` 返回控制端点不存在，已启用进程核验的本地执行事件来源。2026-11-03 实测已识别当前正在工作的 Codex 会话；一次冷读取约 91ms，随后增量读取约 29ms。这是本机一次测量，不代表通用性能承诺。结束、中止、进程退出及记录异常通过合成数据回归验证。

其他 Agent 的原生会话观测、完整聊天历史浏览，以及跨实例停止或追加均未实现。当前公开片段分析不等于完整历史阅读或控制权限。

## 内部审批会话

按 session_meta 的来源排除 Codex 内部 guardian 审批会话，来源为 subagent.other=guardian；不把它们当作用户交代的任务，不提取公开片段交给总控，不生成报告或微信推送。已被识别的旧内部报告从普通对话、消息中心和未读数中排除，原始本地审计记录保留，重启仍生效。此项按明确来源元数据过滤，不按标题文字猜测，也不扫描已关闭的全部历史。
