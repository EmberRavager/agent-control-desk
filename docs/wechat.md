# 个人微信接入

ACD 按腾讯公开的 [iLink／ClawBot 协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md) 实现独立文本通道；不依赖本机 OpenClaw，不读取微信本地数据库或其他聊天记录。协议参考核对日期为 2026-11-03。

当前状态：2026-11-04 已完成本人真实扫码、固定测试消息和总控正文双向收发，用户已在手机确认收到。完成报告推送另有独立开关与验收，连接状态不等于所有功能均已验证。公开客户端文档并不保证每个账号、每种环境均能完成登录或实际收到发送结果，需使用本人账号确认。

## 桌面端

1. 更新构建后，在无进行中任务时停止旧后台，再重新打开 ACD。入口为“设置 → 个人微信”。
2. 微信新任务默认使用 ACD 数据目录下的 `workspace`，首次连接时自动创建；可以直接扫码，也可先更换文件夹。已有自定义目录会保留，该设置不改变已有任务的目录。
3. 微信发起的提问和任务会收到后续答复与结果。“同步桌面任务进展”只控制桌面发起的普通回复、任务状态及确认问题。另有“推送完成报告与建议”，默认关闭，明确启用后将今后报告的任务名、结果摘要和建议发给当前绑定者；不补发旧报告，不发送执行日志或文件。
4. 点击“扫码连接微信”，本人用微信扫码并在手机确认。若要求手机验证码，在设置页填写。
5. 先从微信发送 `/帮助`，确认手机实际收到回复，再发一个只读任务并核对桌面总控中的同一任务。

完成报告推送只由“推送完成报告与建议”控制。开启开关时，ACD 记下当前已经就绪的报告位置。此后模型判定用户委托确已交付、报告就绪时，ACD 为当前绑定者创建一条待发记录。超过聊天窗口的 200 条限制或重启后台，都可以按这条记录继续投递。升级已有订阅时保留原投递状态，不补发过去不可见的旧报告。微信自己发起的任务仍会收到执行反馈。

“已连接”表示轮询接口可用，“最近提交反馈”表示微信接口接受请求，都不等于手机已经收到。必须实际检查双向消息。

暂停期间保留登录和已订阅的待发反馈。恢复连接后继续发送尚未提交的反馈。关闭某类推送会撤销该类待发项，再次开启时从此刻算起。重新扫码中断时，可以恢复先前有效的绑定及其设置。断开并移除登录会停止通道、删除本机凭证；这不等于已在微信侧删除机器人联系人或撤销所有平台绑定，可在手机端另行处理。上述操作不会停止已经交给执行 Agent 的任务。

## CLI

```sh
acd wechat login --project /absolute/path/to/project
acd wechat status
acd wechat test
acd wechat configure --reports --no-notify
acd wechat configure --no-reports
acd wechat verify 012345
acd wechat pause
acd wechat resume
acd wechat disconnect
```

`login` 省略 `--project` 时使用当前目录。它在终端显示二维码后返回，后台继续等待扫码；用 `status` 查询。默认同步桌面普通反馈，传 `--no-notify` 可关闭；关闭后微信主动发起的请求仍会回复。完成报告默认关闭，可用 `configure --reports` 明确开启。`test` 在配对并收到首条微信消息后，向绑定者提交一条固定测试文字；接口成功仍需本人检查手机。命令支持 `--json`；登录响应中的二维码内容用于本人配对，不应公开分享。

## 微信中的操作

| 输入                            | 行为                                                       |
| ------------------------------- | ---------------------------------------------------------- |
| 普通文字                        | 交给同一个总控理解，创建或补充任务                         |
| `/帮助`                         | 查看指令                                                   |
| `/状态` 或 `/任务`              | 查询最近任务、待处理问题与未确认操作提示                   |
| `/报告`                         | 主动查询最近就绪且可见的报告和建议，含已移出聊天窗口的报告 |
| `/停止 完整任务编号`            | 请求停止既有任务                                           |
| `/完成 完整任务编号`            | 检查交付后确认完成                                         |
| `/回答 完整问题编号 选项或说明` | 回答澄清或授权问题                                         |

任务和问题使用桌面端同一编号。原生授权只接受列出的选项；自由说明用于澄清，不会绕过原生授权限制。长反馈会截断并提示在桌面查看。

## 运行与恢复边界

- 只接受扫码绑定者的一对一文字消息，拒绝其他发送者、Bot 自身消息和群消息；暂不处理媒体、文件或语音。
- 本机后台必须保持运行并联网。电脑睡眠/关机期间不能代跑，微信通道本身不会把本地 Agent 变成云服务。
- Bot token 与回复 context token 保存在独立系统凭证账户，按 ACD 数据目录隔离；不返回桌面或 CLI，不写入对话和 SQLite。
- 游标、入站去重、发送状态复用现有 SQLite `Store`。已绑定且启用的通道在后台重启后尝试恢复，失效登录要求重新扫码。
- 处理到一半的入站控制和发送中的出站反馈在重启后标记为待核对，不自动重放。可以查 `/状态`，在桌面核实原任务；不能把超时当作操作未发生。
- 未确认的出站提交不自动重发；未发起的待发送反馈可以继续处理。微信接口返回成功只记录为“已提交”，不声明已经送达或已读。
- 每个响应上限 1 MiB，响应超限时拒绝处理并按连接错误退避。单批消息上限 100 条，超过时在执行前暂停并保留游标，显示明确错误。当前没有大积压分页恢复界面。
- 模型路由能力、Claude 授权限制和任务重启恢复边界与桌面/CLI 相同。

## 已有验证

2026-11-04 真实 iLink 二维码配对成功，用户确认手机收到固定测试消息与总控正文。修复关闭桌面同步同时屏蔽微信正常答复，以及发送期间新回复滞留待发送队列的竞态；发送成功响应兼容腾讯客户端允许省略 ret 的情况。

同批重复入站不会覆盖更新的回复上下文。后台保留最近 256 个请求的回复上下文，较早请求及后台重启后的主动消息使用绑定会话中最近保存的上下文。

使用 Fake 微信 HTTP、Fake vault 和临时目录验证 QR POST、手机验证码界面、绑定者隔离、重复消息、任务控制、授权选项、失效会话、发送结果未知、处理超限和恢复。实际运行 CLI 验证二维码输出、状态查询、暂停/恢复和移除登录。上述 Fake 验证与本轮本人扫码、手机确认收发的记录分别保留，不能据此推断所有账号或网络环境均通过。

## 手机送达记录

本人曾确认固定测试消息和总控正文收到，随后也反馈过报告已提交但手机未收到，连同固定测试与 `/状态` 一度中断。修复补充了腾讯 notifyStart/notifyStop 注册、uint64 消息编号无损解析、请求来源关联与发送队列恢复。2026-11-04 用户已反馈手机恢复收件。本次针对聊天窗口和 AI 交付判定的改动使用 Fake 微信验证，没有另外发送真实消息。

已提交但未确认到手机的报告不自动重放；可以从微信主动发送 /报告 取得最近报告。暂停、恢复、重启不会把未知控制或发送重新执行。

测试推送缺少服务器消息编号时，CLI 测试返回待核对的错误，设置页显示“微信送达待核对”。普通发送保留原回执，已提交的消息不自动重发。腾讯仓库有用户报告相同的无编号回执与手机未收件现象，见 [问题 371](https://github.com/Tencent/openclaw-weixin/issues/371)。
