# 定时任务

ACD 可以保存定时计划，在本机后台到达指定时间时，将计划中的要求交给已接入的执行 Agent。每次触发创建独立任务，复用原有执行适配器、目录冲突保护、输入授权、完成报告和交付检查；计划编号、触发记录编号与执行任务编号分别保存。

桌面端左侧的“定时任务”提供新建、编辑、暂停、恢复、删除和触发记录。总控对话也可以根据明确的要求创建或管理计划；缺少执行者或无法确定具体时间时，应先澄清；未指定时区时使用当前系统时区。创建计划只保存计划，不立即执行工作。

## 时间规则

| 类型     | 示例                                | 规则                                                                  |
| -------- | ----------------------------------- | --------------------------------------------------------------------- |
| 单次     | 2026-12-01 09:00，UTC+08:00         | 保存带偏移的绝对时间；必须是未来时间                                  |
| 固定间隔 | 每 60 分钟                          | 1–525600 分钟；从创建或更改时间规则后的下一个间隔开始，按固定锚点推进 |
| 每天     | 每天 09:00，Asia/Shanghai           | 在指定 IANA 时区的当地时间执行                                        |
| 每周     | 每周一、三、五 09:00，Asia/Shanghai | 星期使用 0（周日）至 6（周六），可多选                                |

每日、每周规则保存其明确时区，不随电脑切换系统时区而改变。夏令时跳过的当地时刻当天不触发；当地时间重复出现时，同一天最多触发一次。间隔规则按经过的分钟计算，不是按当地钟表时间。

暂停后不触发，恢复时从未来的下一次时间开始；单次时间已过去时需要编辑时间。编辑只影响未来触发，已经创建的任务保留原有要求、执行者和目录。

## 本机运行和错过时间

定时执行依赖 ACD 后台服务运行、电脑唤醒以及工作目录可访问。关闭窗口或退出桌面端不会停止已经独立运行的后台；`acd service stop` 会停止调度。电脑关机、休眠或后台退出时，不提供云端代跑，当前也没有系统自启动保证。

后台每秒检查已保存的下次执行时间。运行中的计时允许最多 60 秒延迟；超过此窗口视为错过，不再补跑。后台重新启动时，所有已经逾期的触发都记录为错过，即使只逾期数秒也不重放。多个周期只合并记录一次错过并推进到未来时间；错过的单次计划结束。错过记录表示未创建执行任务，不表示工作已经完成。

同一计划前一轮仍为 `queued`、`running`、`waiting_input`、`blocked`、`stopping` 或 `unknown` 时，本轮记录为跳过，避免排队堆积或重复外部操作。执行正常结束进入 `review` 后允许下次触发；`review` 仍需用户检查，不代表业务结果已验证。不同计划和普通任务继续遵守同目录、父子目录串行保护。

暂停或删除计划不会停止已经触发的任务；需要停止时，在任务详情中操作或运行 `acd stop <任务编号>`。重启后遗留执行仍遵守原有 `unknown` 与人工核对规则，不自动重跑。只有核实原执行确实停止后，才使用 `acd recover <任务编号> --stopped` 释放占用。

## CLI

先用 `acd agents list` 查找已选择且可用的执行 Agent 编号。将以下内容保存为 `schedule.json`，替换 `agentId` 和 `cwd`：

```json
{
  "name": "每天检查启动指南",
  "prompt": "检查 README 的启动说明与源码是否一致，只分析并汇报，不修改文件。",
  "agentId": "从 acd agents list 获取的编号",
  "cwd": "/absolute/path/to/project",
  "rule": {
    "kind": "daily",
    "time": "09:00",
    "timeZone": "Asia/Shanghai"
  }
}
```

`cwd` 可省略，CLI 使用调用命令时的当前目录。显式填写时必须是绝对路径。创建和更新都使用完整 JSON；文件不允许未知字段。计划中不保存模型 Key 或原生 Agent 登录信息，执行时沿用已接入 Agent 的原生配置。

```sh
acd schedules --help
acd schedules create --file schedule.json
acd schedules list
acd schedules show <计划编号>
acd schedules update <计划编号> --file schedule.json
acd schedules pause <计划编号>
acd schedules resume <计划编号>
acd schedules runs <计划编号>
acd schedules delete <计划编号>
acd schedules list --json
```

其他规则的 `rule` 写法：

```json
{ "kind": "once", "at": "2026-12-01T09:00:00+08:00" }
```

```json
{ "kind": "interval", "minutes": 60 }
```

```json
{
  "kind": "weekly",
  "time": "09:00",
  "timeZone": "Asia/Shanghai",
  "days": [1, 3, 5]
}
```

单次时间必须包含 `Z` 或明确偏移，不能使用不带时区的日期字符串。`--json` 返回结构化计划或记录；`runs` 返回最近 30 次触发。`dispatched` 仅表示已创建执行任务，结果应查看关联任务及报告，不能把触发成功当作业务成功。

旧后台没有 `schedules` 能力时，客户端拒绝提交并提示更新。先处理进行中的任务，再运行 `acd service stop`，使用更新后的源码启动后台；关闭窗口本身不会更新仍在运行的后台。

## 本机 API

所有接口沿用本机客户端认证和 Origin 限制，SSE 快照包含可选的 `schedules` 列表。

| 请求                             | 内容或返回                               |
| -------------------------------- | ---------------------------------------- |
| `GET /api/schedules`             | 计划列表                                 |
| `POST /api/schedules`            | 完整 `ScheduleInput`，返回新计划         |
| `PUT /api/schedules/:id`         | 完整 `ScheduleInput`，替换未来要求与时间 |
| `POST /api/schedules/:id/pause`  | 暂停计划                                 |
| `POST /api/schedules/:id/resume` | 恢复计划                                 |
| `POST /api/schedules/:id/delete` | 删除计划，保留已触发任务                 |
| `GET /api/schedules/:id/runs`    | 最近 30 次触发记录                       |

共享 Schema 位于 `packages/contracts/schedules.ts`。后台保存规范化工作目录，校验目录、已选择执行者、时间和时区。触发时再检查可执行条件，不因创建时可用就假设永远可用。计划与触发记录使用现有 SQLite 实体存储，进入原有 Runtime 执行链路。

当前验证以隔离 Fake Agent、Fake 模型、本机临时端口和临时目录为主。真实模型的长期定时执行、休眠唤醒、安装包升级与跨平台行为仍需分别验收。
