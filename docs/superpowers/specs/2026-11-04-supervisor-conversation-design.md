# ACD 总控对话与代答设计

用户希望留在总控聊天中委派、接收答案和处理必要的追问。用户已选择对话式总控；此前考虑过的自动进入任务对话和自动跳转原生 Agent 都会打断当前聊天。详细执行过程通过已有任务列表按需查看。

## 以一次天气查询为例

1. 用户说“问下 Codex 今天天气”。成功接收并创建任务后，总控回复“收到，我去问 Codex。”保持当前对话和输入焦点。排队或派发失败时如实反馈。
2. Codex 收到“今天天气怎么样？”。执行者、工作目录和会话标识作为路由信息单独传递。
3. Codex 问城市时，若用户已在本次任务中明确说过“这次查杭州”，ACD 将“杭州”续发到原会话。如果只知道用户曾经查询杭州，总控在当前对话问一句“你想查哪个城市？”。用户直接回复即可。
4. 执行者返回天气后，总控直接呈现城市、天气和气温，并保留原答案里的必要来源或不确定性。简单问答到答案为止。需要验收的文件或代码交付仍保留已有的任务检查机制。

## 消息边界

总控显示委派回执、必要的用户问题和最终答复。进度事件、完整原文、代答记录和任务操作放在相应任务详情中。主动委派的任务按来源关联到当前总控对话。其他原生会话的完成报告留在其任务入口。

同时点名多个执行者时，每个执行者收到独立的提问，答复标注执行者。续聊按原任务与原生会话关联。多个待答问题同时存在且无法判断归属时，用一句话说明需要区分的对象。

## 代答规则

只有当追问是信息补充、答案能够从本任务中用户明确给出的事实或要求唯一确定、且适配器支持安全续接时，才自动回复。普通文字回复与原生授权请求分别处理。权限批准、扩大操作范围、不可逆操作及用户偏好冲突交回用户决定。消息历史、工具输出与执行者自身的猜测不构成用户授权。

以任务、轮次及问题或回复标识去重，记录答案依据与送达状态。未确认送达、问题过期或被重复追问时停止自动转发。对于以普通最终文字提出的追问，需要验证识别与续接链路，不能只依赖结构化输入事件。

## 验收

用隔离执行者覆盖派发、排队、失败、已知城市自动续接、未知城市在总控询问、授权请求、普通文字追问、重复事件、并行任务归属。检查原生会话实际收到的文本，总控内答案可直接阅读，侧栏可查看执行详情。明确区分各适配器已验证的能力。

同一指令中的独立目标可分别交给 Codex 的多个会话。派发回执展示真实执行者、实际下发的指令与排队情况。每轮回复保留原任务和会话归属。
