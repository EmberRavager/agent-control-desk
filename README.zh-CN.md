**One conversation. All your agents.**

Agent Control Desk（ACD）是一个在本机运行的 Agent 调控中心，核心是**任务分发路由和多会话管理**。你可以在同一个对话中交代工作，让 ACD 将任务分配给 Codex、Claude Code、OpenCode 或 Pi，并集中查看各项任务的进展、待处理问题和交付结果。

每项任务拥有自己的执行会话。你可以继续交代新任务，也可以为已有任务补充要求、回答问题、请求停止或继续修改。桌面端、CLI 和个人微信入口共用同一个本地后台与任务状态。

ACD 当前处于本地测试阶段，已提供 Mac ARM64 桌面安装包。

## 为什么做 ACD

做 ACD 的想法受到 Personal Agent 的启发。我工作时经常同时打开多个 Agent session，让它们分别执行不同的任务。会话一多，就很容易混淆：最初给每个对话下达了什么任务，后来补充了哪些要求，现在进行到哪里，下一步又该做什么。

这些会话各自执行，却缺少一个统一的调控和汇报入口。我需要在多个窗口之间反复切换，重新阅读上下文，才能把任务和进展对应起来。

我希望通过一个对话框统一交代工作、跟进各个 session、接收结果汇报。ACD 因此从任务分发和多会话管理做起，让分散的执行围绕各自的目标组织起来。

## 核心功能

### 任务分发与路由

总控会结合当前消息、工作目录、近期对话和已有任务，判断你是在讨论问题，还是需要新建、补充、查询或停止任务；目标不明确时先询问归属。一条要求可以拆成多项任务，普通讨论不会默认变成执行任务。

新任务可以手动选择执行 Agent，也可以自动分配。自动分配先查项目排序，再查全局排序，选用排名最高的合格执行者。如果都未命中，再结合合格候选和总控建议选择；所有候选都要满足已接入、可用和必需的协议能力。你明确指定的 Agent 无法承接时，ACD 会说明原因，保留消息供你调整，并在任务详情中显示实际分配依据。

总控模型单独配置；执行 Agent 继续使用各自的模型、账号、工具和项目设置。具体规则见 [任务路由与分配](docs/routing.md)。

### 多会话与任务管理

- **一个入口，分别跟进。** 新任务使用独立的执行会话，各自保存目标、进展和结果；继续已有任务时沿用原 Agent 和会话。
- **并行处理多个项目。** 不重叠的工作目录可以并行；相同目录或父子目录的任务排队等待，期间仍可发送消息。已观测到的原生 Codex 执行也纳入目录占用检查。
- **集中处理问题。** 从同一个总控回答任务中的补充问题和执行端支持的授权请求，查看需要你处理的事项。
- **跟进到交付。** 总控对照任务目标和公开结果，在判断有新交付时生成摘要与下一步建议。托管任务先进入待检查状态，由你确认完成；也可以继续修改。建议不会自动启动新任务。
- **查看原生会话。** 同步已接入 Codex 的当前会话状态，通过任务标题、目标、当前步骤、阻塞和下一步了解执行情况。这部分为只读观察，不导入完整聊天历史。
- **保留对话与草稿。** 任务和总控对话保存到本机，草稿及未确认发送的记录可在重开窗口后恢复。支持任务搜索和定位，以及对尚未进入动作应用阶段的失败消息重新判断。

### 支持的 Agent

| Agent          | 新建与续接任务 | 执行中追加要求 | 交互能力                   |
| -------------- | -------------- | -------------- | -------------------------- |
| Codex          | 支持           | 支持           | 部分原生授权和文字输入请求 |
| Claude Code    | 支持           | 不支持         | 当前无交互授权             |

## 安装与首次使用

### 1. 安装 ACD

Mac ARM64 使用 DMG 或 ZIP 中的 `Agent Control Desk.app`，复制到 Applications 后打开。桌面包自带运行时，无需安装 Node.js。本地构建的安装包位于 `release/`；版本、构建和升级步骤见 [安装与分发](docs/distribution.md)。

当前安装包用于本地测试，使用 ad-hoc 签名，尚未完成 Apple 公证。Windows 原生构建与运行仍待验收。

### 2. 接入执行 Agent

先在原生工具中完成 Agent 的安装、登录和配置，再从 ACD 的“连接”中选择要接入的 Agent。自动发现没有找到程序时，可以手动选择其路径。

接入检查确认程序能否启动；账号权限和实际可用性以任务执行反馈为准。

### 3. 配置总控模型

打开“设置 → 模型接入”，选择服务商并填写模型与所需凭证。也可以连接本机 Ollama 或 LM Studio。总控负责理解、分配和汇总，执行 Agent 的模型不受这项设置影响。详细说明见 [配置与本地数据](docs/configuration.md)。

### 4. 发出第一个任务

选择一个工作目录，在总控中输入：

> 检查这个项目的 README，告诉我如何启动。先只分析，不要修改文件。

保持“自动分配”，或选择本次新任务的执行者。在“设置 → 任务分配”中可将 Agent 按优先级从高到低排列，分别保存项目排序和全局排序。

### 5. 跟进并检查结果

在总控和侧栏查看进展，按任务关联补充要求或回答问题。执行结束后检查交付结果，再选择“确认完成”或“继续修改”。后续切换新任务的工作目录，不会改变已有任务的目录。

## 常见操作

### 在总控中交代工作

| 你想做什么   | 示例                                                   |
| ------------ | ------------------------------------------------------ |
| 分成多个任务 | “分别检查项目启动方式和测试覆盖，两个任务都先只分析。” |
| 指定执行者   | “这项检查交给 Codex。”也可使用输入区的执行者选择器     |
| 补充已有任务 | 选中任务后发送：“加上边界情况，其他要求不变。”         |
| 查询进展     | “现在各个任务进行到哪里了？”                           |
| 停止任务     | 明确关联任务后发送：“停止这个任务，保留已有修改。”     |
| 定时执行     | “每天北京时间 9 点检查这个项目最近一天的变更并汇报。”  |

定时计划也可以直接在“定时任务”页面创建和管理，无需调用总控模型。计划使用固定执行者；输入区的本次执行者与能力选项用于立即新建任务。详见 [定时任务](docs/schedules.md)。

### 选择语言

在“设置 → 外观 → 语言”中选择简体中文（`zh-CN`）或英文（`en`），然后保存。桌面端与 CLI 使用同一数据目录时共享已保存的语言偏好，已有对话和任务原文保持不变。CLI 用法与切换范围见 [语言设置](docs/configuration.md#语言设置)。

### 使用 CLI

安装 CLI 包，或在源码构建后运行 `npm link`，即可使用 `acd`：

```sh
acd                                      # 打开总控对话
acd send "只读检查项目启动方式并汇报"
acd tasks                                # 查看 ACD 发起的任务
acd sessions                             # 查看已同步的原生会话
acd inbox                                # 查看消息与未读
acd schedules                            # 查看定时计划
```

需要指定执行者或设置优先级时，先从 `acd agents list` 获取编号：

```sh
acd send "检查项目，执行中需要追加要求" --agent <Agent编号> --require steer
acd agents default <首选编号> <次选编号> --project /absolute/path/to/project
```

使用 `acd --help` 查看停止、回答、确认完成等命令；常规查询支持 `--json`。CLI 安装方式见 [安装与分发](docs/distribution.md)，更多命令见 [开发与 CLI 指南](docs/development.md)。

## 从源码运行

需要 Node.js ≥ 22.13.0 和 npm。在项目目录执行：

```sh
npm ci
npm run build
npm run desktop
```

桌面端会启动或复用本地后台。关闭窗口后默认保持驻留；明确退出桌面端也不会停止任务服务。需要停止后台时使用 `acd service stop`，从仓库运行时可用 `node apps/cli/acd.mjs service stop`。

开发命令、工程结构和打包入口见 [开发指南](docs/development.md)。

## 使用边界

- ACD 在本机执行和保存状态；电脑需保持唤醒，后台需运行。定时任务错过时间不补跑，同一计划上一轮未结束时跳过本轮。
- ACD 使用你配置的模型服务处理对话、摘要和报告，相关内容会发送到该服务。模型凭证与微信登录保存在操作系统凭证存储中；数据范围见 [配置说明](docs/configuration.md)。
- 目录排队用于减少已知的执行冲突，不提供自动 Git worktree、修改合并或回滚。请求停止不会撤销已有修改。
- 后台重启或连接丢失后，部分执行状态需要人工核对。ACD 不会自动接管或重跑结果不明的任务，恢复方式见 [消息与任务恢复](docs/message-recovery.md)。
- 原生外部会话目前只观察 Codex，不支持通过 ACD 追加或停止这些会话。个人微信仍处于试用阶段，手机端消息送达和完成报告推送尚待确认；系统通知也有待实机验收的行为。支持范围和最新验证记录见 [功能状态](docs/product-status.md)。

## 接下来

当前版本已实现任务到 Agent 的分发与会话管理。接下来希望进一步做好以下几件事：

- **判断任务难度。** 理解任务的复杂程度，为执行选择提供依据。
- **模型路由。** 根据任务难度，在执行 Agent 可用的模型中选择合适的模型来处理任务。
- **提高决策水平。** 逐步改善对任务理解、拆分、分配、执行进展和交付结果的判断，让总控更准确地掌握每项工作的目标与状态。

这些属于后续方向；当前尚未实现按任务难度自动选择执行模型。
